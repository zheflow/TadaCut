# 全局创作助手

Agent 的技能加载、任务计划、上下文、记忆与中断恢复能力见 [基础能力清单](agent-foundation.md)。

助手位于 App 外层的右侧面板，在工作台、项目、素材、模型、技能、扩展、任务和设置之间保持同一段对话与未发送的草稿。工作台的检查器独立显示；窄窗口下助手为可收起的侧栏。打开工具表单时，右侧对话仍可使用。

## 页面与引用

每次发送、继续任务或确认待执行操作，都会附上当前页面、工作区、项目、时间线、播放头、主题、对话模型与模式，以及所引用对象的类型、ID、名称和所属项目。项目列表分类、素材搜索与分类、技能搜索与分类、故事子页、资源库子页也进入上下文。页面文字作为数据处理，不扩大工具权限。

`read_app_context` 可以重新读取实际窗口，避免长任务使用旧页面状态。请求绑定发起消息的窗口和项目；事件有有效期、确认回执和重放去重。切换页面保留项目绑定，切换项目用 `open_project` 并结束当前轮次，下一条消息使用新项目的会话。

素材支持 ⌘ / Ctrl 多选与 Shift 连选，时间线支持 ⌘ / Ctrl 切换选择、Shift 追加和编组联动。助手逐项显示片段、素材、项目、技能、模型、任务和扩展引用，可逐项移除或清空，一次最多 100 项。素材库引用包含来源项目，不以同名素材猜测目标。

多选素材拖入时间线会依次排列，作为一次事务撤销。多个片段可一起拖动，显示目标轨道、帧位置与有效状态；锁定、不兼容和碰撞会阻止提交，Esc 取消拖动。

## 工具覆盖

工具目录包含原有剪辑与应用管理能力，以及 0.2 新增的高级画面、媒体处理、录制、画布关系与团队协作工具；内置 `/studio` 提供工作室管理流程。当前完整工具目录可通过 `/api/agent/tools` 读取；它是宿主的能力目录，不会整体发给模型。新增功能逐项映射见 [advanced-features.md](advanced-features.md)。

## 技能与按需加载

0.2.1 统一使用技能引导的工作流。系统提示仅给出最多 3 个相关技能的简短目录，模型通过 `read_skills` 搜索（每页 8 项）、`load_skill` 读取选中的工作流；参考文件通过 `read_skill_file` 按需读取。用户手动选技能或用斜杠命令时，也只先传技能名称与 ID。是否实际加载可在聊天的“上下文与技能”查看，不会把仅推荐的技能算作已经使用。

API 模式保留少量核心工具，`tool_search` 每次只加载最多 6 个匹配工具；最近使用的额外工具最多保留 12 个，工具定义总字符数另有限制。新用户消息会重置额外工具集合；继续任务和批准待执行操作会保留本轮需要的工具。不会因命中一个关键词而展开整组工具。

Codex、Claude Code、Copilot 的协议采用固定的 8 个入口：`read_project`、`read_app_context`、`read_skills`、`load_skill`、`search_memories`、`ask_user`、`tool_search`、`call_tool`。具体操作先搜索参数定义，再经 `call_tool` 调用，实际工具仍经过相同权限检查。完整目录和执行代码保留在宿主。这个技能层属于 TadaCut，并不依赖外部 CLI 的同名技能目录。

## 记忆、历史与压缩

长期偏好与项目约定分别持久化；每次按当前请求召回，两个范围各最多 8 条、各 2,400 字符。相关条目优先于无关的新条目，重复文本去重；更完整的记忆可用 `search_memories`、`list_memories` 查询。当前用户要求优先，其次是项目约定、全局偏好。聊天摘要不会自动成为长期记忆。

明确要求“记住”可使用 `remember`。偏好学习默认关闭；启用后，API 模式可提取候选，外部 CLI 可通过 `suggest_memory` 提出候选，均需用户确认后才进入长期偏好。整理记忆会校验模型返回结构和并发修改，全局替换使用数据库事务，防止部分写入或删除整理期间新增加的记忆。

API 与外部连接都保存用户消息、实际工具调用、结果和助手答复，重启或切换连接后仍可带入同一项目的历史。外部连接无需依赖某个短命 CLI 进程的会话 ID。新请求发出前按系统提示、工具定义、消息和画面合计估算输入，默认预算约 24,000 tokens；这个保守估算不等同于服务计费 tokenizer。

超过预算时，在完整工具调用边界压缩旧历史，保留当前真实用户要求和待确认调用；单条用户消息触发的长工具循环也可以压缩。API 模式先尝试模型摘要，失败后使用本机摘录；外部连接使用本机工作摘要。旧工具结果可以重新读取，优先压缩其细节；无法在保留当前要求的前提下满足预算时明确报错。截图以图像内容传递，不把 Base64 放进文字上下文；工具文字结果最多 16,000 字符。

上述预算作用于应用组装的请求。外部 CLI 在一次运行内部可能多次请求模型，其内部上下文压缩由各运行时管理，应用不宣称能统一控制或精确测量。聊天用量标为“累计输入 / 输出”；“上下文与技能”另列应用输入估算、工具数、已加载技能、预载记忆与应用压缩次数。摘要有信息损失，关键状态始终以重新读取项目、任务与待应用方案为准。

## 权限与外部运行时

应用管理使用独立的 `manage` 权限，默认询问。助手不能放宽自己的权限、默认模式，也不能把对话切换到自动模式；已保存密钥的服务改类型或地址必须由用户在模型页完成，避免密钥被发往新地址。手动模式的项目编辑仍进草稿；应用配置经过确认后直接保存，不伪装成时间线提案。发布总是逐次确认，技能不扩大权限；问答模式只提供读取工具。

Codex、Claude Code、Copilot 在 App 中使用相同的权限守卫，允许、询问、拒绝都在执行前判断；跨项目切换后拒绝本轮的后续动作。外部工具调用依次执行，避免并行调用跨过项目切换。Codex / Copilot 的原生非项目工具保持关闭；Claude 使用单次运行的本机 MCP 连接、随机凭据和限定目录，结束后关闭连接并删除临时配置。设置页提供的通用 MCP 连接仍是独立的读取 / 编辑会话接口。

凭据只在宿主库保存。公开模型 DTO 只有 `hasKey` / `keyUnreadable`，聊天不能读取、代填或导出密钥。界面操作采用明确类型的动作及回执，模型没有任意 HTTP、DOM 点击或 shell 工具。

## 外观

没有已保存外观偏好的用户默认使用白色浅色外观：页面与面板为白色，层次用中性灰；蓝色 `#2f6fed` 只标出可点击、已选中和当前所在的元素；红色只用于错误，绿色表示成功或已连接，橙色表示需要留意。片段按类型区分颜色：画面蓝、音频棕、字幕紫、动画青绿。粉色只保留在品牌标志上。墨绿深色和跟随系统选项保留。

助手运行失败时，消息下方以红色区块写明服务或运行时给出的原因，例如 HTTP 状态和服务返回的错误说明；外部运行时重试时显示进行中的提示。

樱花枝线与轻微花瓣是可选装饰，默认关闭，可在设置中打开；装饰不截获鼠标、不进入画面预览或导出，系统减少动态效果时停止动画。原生窗口背景和菜单颜色跟随所选主题。
